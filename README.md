## 夜族崛起服务端到底吃什么资源

《夜族崛起》（V Rising）的专用服务端是 Stunlock Studios 官方免费提供的，通过 SteamCMD 获取，App ID 是 `1829350`，不需要显卡。它是 Windows 原生程序，Linux 上要跑就得套一层 Wine 或用 Docker 镜像。

关键点在于：城堡模拟、血池、仆从任务这些计算主要压在**主线程**上。所以挑机器时，一颗高主频的 CPU 比一堆低频核心有用得多。几个托管商给出的配置口径基本一致：

| 同时在线人数 | 内存 | CPU | 硬盘 |
| --- | --- | --- | --- |
| 2–8 人（小队 PvE） | 4–6 GB | 2–3 核，主频越高越好 | 10–15 GB SSD |
| 10–20 人（日常 PvP） | 6–8 GB | 4 核 | 15–20 GB SSD/NVMe |
| 20–40 人（多城堡、城堡战争） | 12–16 GB | 6 核以上高主频 | 20 GB 以上 NVMe |

装 mod 的话，额外再留 2–4 GB 内存比较稳妥，内容类 mod 尤其吃内存。

网络这块，参考口径是 2–8 人至少 10 Mbps 上传，10–30 人要 25–50 Mbps。端口固定两个，都是 UDP：**9876 是游戏端口，9877 是 Steam 查询端口**。两个都要放行，少一个后果都不一样。

> 硬盘别只按"装得下"来算。服务端本体 3 GB 出头，但存档会随着城堡数量持续变大，官方文档和托管方的建议值都在 10–20 GB。用 NVMe 对存档读写和重启加载帮助明显。

## 固定计费还是动态计费

雨云游戏云支持两种计费方式，这是决定成本的大头。

固定计费就是传统按月租，跑满一个月价格不变。动态计费则把基础月租压得很低，然后按每天 CPU 超出 20% 基准线的部分再日结一次"电费"，内存等其他硬件不产生这项费用。

怎么选看你的作息：

- 每天都开、一开就是几个小时，甚至想让它 7×24 挂着 → **固定计费**，账算得清楚。
- 只在周末和节假日拉朋友进来打几局，平时世界关掉 → **动态计费**，闲置时间几乎不花钱。

另外，官网游戏云页面明确标注了新用户可领首月 5 折券，年付也另有折扣，两个叠加后单月成本能明显低于标价。不放心的话可以先买一个月试，雨云提供 7 天内无理由退订（每个账号限 3 次），购买后还有 10% 以上的积分返利可以提现或换券。

## 路线一：Windows 远程桌面开服，最省事的一条

这是踩坑最少的方式，因为服务端本来就是 Windows 程序。

1. 本地按 `Win + R`，输入 `mstsc` 打开远程桌面，连上你的服务器。
2. 在服务器桌面新建一个**纯英文名**的文件夹，比如 `vrserver`。中文路径后面容易出问题。
3. 下载 SteamCMD，把 `steamcmd.exe` 放进这个文件夹。
4. 文件夹里左上角"查看"勾上"文件扩展名"，新建一个文本文件，重命名为 `update.bat`。
5. 右键编辑 `update.bat`，写入这一行并保存：


steamcmd.exe +login anonymous +app_update 1829350 validate +quit


6. 双击运行 `update.bat`，黑窗口会自动下载服务端。跑完后窗口自己关闭，文件夹里会多出一堆文件。
7. 沿着 `steamapps\common\VRisingDedicatedServer` 进去，这里就是服务端根目录。
8. 配置文件在 `VRisingServer_Data\StreamingAssets\Settings`，里面两个 JSON：`ServerHostSettings.json` 管连接，`ServerGameSettings.json` 管玩法。
9. 用记事本打开 `ServerHostSettings.json`，至少改这几项：

json
{
  "Name": "我的吸血鬼世界",
  "Port": 9876,
  "QueryPort": 9877,
  "MaxConnectedUsers": 15,
  "SaveName": "world1",
  "Password": "设一个进服密码",
  "ListOnSteam": true
}


10. 回到服务端根目录，双击 `VRisingServer.exe` 启动。看到控制台输出 `Startup Completed` 之类的完成提示，服务端就算起来了，**这个黑窗口不要关**。
11. 进游戏连接：开始游戏 → 线上游戏 → 显示所有服务器 → 直接连接，填 `服务器IP:9876`，冒号用英文的。

管理员权限靠 `adminlist.txt` 解决，每行放一个玩家的 Steam64 ID，保存后重启服务端生效，最多 4 个管理员名额。

## 路线二：Linux + Docker，习惯命令行的话更轻

Linux 下用 `trueosiris/vrising` 这个镜像比较省事，它每次启动会自己检查并更新服务端。核心是把两个 UDP 端口映射出去：

yaml
services:
  vrising:
    image: trueosiris/vrising:latest
    restart: unless-stopped
    ports:
      - "9876:9876/udp"
      - "9877:9877/udp"
    volumes:
      - ./data:/mnt/vrising/server
      - ./saves:/mnt/vrising/persistentdata


第一次启动要通过 Steam 拉 2–3 GB 的服务端文件，耐心等日志跑完。有个前提要有心理准备：服务端是 Windows 程序，Docker 方案靠 Wine 转译，性能会有损耗，稳定性还行。追求帧稳和低延迟的话，同样的配置还是 Windows 原生更好。

## 开服之后，值得花十分钟改的几项

服务端能跑只是及格线，下面这些才决定你的世界好不好玩：

- **GameModeType**：决定 PvE 还是 PvP，一开始定错，后面改起来要重开世界。
- **PvP 与攻城时段**：可以按时区限制只在晚上开放 PvP，白天专心造城堡的玩家会很感激这个设置。
- **资源与掉落倍率**：想加快进度就调高，但倍率和血族强度是两回事，别一起拉满。
- **昼夜时长**：白天时长直接决定玩家被太阳逼进地洞的频率。
- **城堡数量上限与城堡衰减**：人多的时候限制城堡数量，能明显降低内存占用和卡顿。
- **备份**：存档目录记得定期打包下载。云主机再稳，也顶不住一次误删。

## 端口、网络，和朋友连不上的原因

雨云的公网 IP 分两种。**NAT 模式**默认共享 IP，靠端口映射对外提供访问，适合游戏开服这类场景；也可以加购**独立公网 IP**，适合想让服务器出现在公网列表里、或者要跑更多服务的玩法。

《夜族崛起》需要两个 UDP 端口，也就是 9876 和 9877，开服前把它们都映射或放行出去。如果你选的是 NAT 模式，下单前建议直接找客服确认一下目标用法，省得开服当天才发现端口对不上。

防火墙也要同步处理。Linux 下是：

bash
ufw allow 9876/udp
ufw allow 9877/udp
ufw reload
ss -ulnp | grep 9876   # 确认端口真的在监听


Windows 下第一次启动 `VRisingServer.exe` 时系统会弹防火墙提示，务必点"允许"。手滑点了拒绝，就得去防火墙高级设置里手动补一条入站规则。

朋友连不上，九成是下面几种情况：

| 现象 | 最可能的原因 |
| --- | --- |
| 直连超时 | 9876/UDP 没放行或没映射 |
| 服务器列表里搜不到 | `ListOnSteam` 是 false，或 9877/UDP 被挡 |
| 能进但很快掉线 | 上行带宽不够，或内存吃满 |
| 加载世界卡很久 | 机械盘或共享 IO，换成 NVMe |
| 人数一到上限就进不来 | `MaxConnectedUsers` 设小了 |
